# AI 协作开发规则

所有参与本仓库的 Codex、WorkBuddy、豆包代理在改动前必须阅读本文件及 `ARCHITECTURE.md`、`DATABASE_BASELINE.md`、`DEV_TASKS.md`，并查看当前分支、工作区状态与任务归属。

1. 只在分配给自己的任务分支工作；不要长期在 `main` 开发，不覆盖其他代理未提交或已分配的文件。提交只包含本任务文件。
2. 每次改动都保持 Laravel/Vue 实现简单、可维护。先满足当前任务，不为推测的未来需求增加抽象。
3. Project 是最高数据隔离边界。任何业务记录、读取、更新、删除、导出和后台任务都必须明确归属 Project。跨项目访问默认拒绝。
4. 用户的业务路径必须先选 Project，再进入 Column 和 Topic。青柠育见、青柠文化、青柠长伴默认互不可见。
5. 不建立“2.5D 图文”独立 Content Profile；栏目、逐页内容、最终上图文案、查重、收尾句均为可复用能力。
6. 一篇 Content Item 只生成一套统一视觉母版。共享资产要区分无文案定稿底图与有文案定稿图。公众号、视频号只建 Channel Task，不复制 Content Item。
7. 文案确认、图稿验收、视频验收、发布各有独立状态。正式版本不可被后续编辑原地覆盖。
8. Lite V1.0 不开发 Windows Local Agent、本地实时监听、双向同步、TTL 云缓存、复杂权限、DAG Workflow、n8n 式编辑器。
9. 发现需求冲突时在架构风险中记录并提出决策点，不擅自改变产品方向。每个任务结束运行测试、修复本任务问题，记录结果并等待审核后合并。
