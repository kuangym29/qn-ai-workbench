## 4. Normalization 规则设计

### 4.1 两种 Normalization 的区分

| 类型 | 用途 | 严格程度 |
| --- | --- | --- |
| **Exact Normalized Form** | 用于 Exact Duplicate 判定 | 保守，只做安全转换 |
| **Overlap Comparison Form** | 用于 Overlap Candidate 发现 | 更激进，便于发现相似但不完全相同的文本 |

### 4.2 Exact Normalized Form（保守）

目的：消除无意义差异，确保真正相同的文本不会因为格式差异被误判为不同。

| 步骤 | 操作 | 理由 |
| --- | --- | --- |
| 1 | Unicode NFKC 标准化 | 兼容全角/半角字符等价形式 |
| 2 | 首尾空白 trim | 消除首尾空格差异 |
| 3 | 连续空白折叠为单个空格 | 消除多空格差异 |
| 4 | CRLF → LF | 统一换行符 |
| 5 | 全角空格（U+3000）→ 普通空格 | 消除全角/半角空格差异 |

**不做的操作**（Exact 判定中保留原样）：
- ❌ 中文标点 ↔ 英文标点转换
- ❌ 中文引号 ↔ 英文引号转换
- ❌ 大小写转换（中文无影响，英文暂不做）
- ❌ 换行符删除或合并

### 4.3 Overlap Comparison Form（激进，仅用于候选发现）

目的：发现可能相似的文本，供人工审核。不用于自动判定。

| 步骤 | 操作 | 理由 |
| --- | --- | --- |
| 1-5 | 同 Exact Normalized Form | |
| 6 | 删除所有标点符号（中文 + 英文） | 中文短文案标点对语义贡献小，删除后便于比对核心词 |
| 7 | 换行符替换为空格 | 换行不影响语义相似度 |
| 8 | 中文引号统一（""''→空） | 引号不影响语义判断 |

**注意**：Overlap Comparison Form 只用于候选发现，**不能**用于自动判定为 duplicate。最终必须人工确认。

## 5. Exact Duplicate 定义

### 5.1 两层 Exact

| 层级 | 定义 | 说明 |
| --- | --- | --- |
| **原文 Exact** | 原始文本逐字符完全相同 | 最严格，连标点、引号、换行都必须一致 |
| **Normalized Exact** | 经过 Exact Normalized Form 后完全相同 | 允许无意义格式差异，但语义字符必须一致 |

### 5.2 输出要求

查重结果必须区分：
- `original_exact = true/false`
- `normalized_exact = true/false`

不能只返回一个 `duplicate = true`。

### 5.3 当前语料中的真实 Exact 案例

**原文 Exact**：
- 当前 4 篇 / 37 页中，无自然的原文 Exact 重复案例。

**Normalized Exact**：
- 收尾句台账中的换行表示（／）与正式版换行（\n）差异：经过 Exact Normalized Form 后，如果将换行视为等价，则积木倒了 / 弟弟想玩车 / 纸箱水果店的收尾句与台账记录为 Normalized Exact。
- 但这属于同一篇的不同来源，不是"跨篇重复"。

## 6. Overlap Candidate 建议

### 6.1 推荐 V1.0 计算方法

**推荐：字符 3-gram Jaccard 相似度**

理由：
1. **适合中文短文案**：中文没有天然分词边界，字符 n-gram 不依赖分词工具，实现简单。
2. **3-gram 粒度合适**：2-gram 太细（容易因单个字符不同产生大量误报），4-gram 太粗（对短文本过于严格）。
3. **Jaccard 直观**：交集 / 并集，结果在 0-1 之间，容易理解和设阈值。
4. **无外部依赖**：纯字符串操作，不需要分词器、不需要向量数据库。

### 6.2 字段级比较建议

查重必须按字段分别比较，不能整篇拼接：

| 字段 | 比较优先级 | 说明 |
| --- | --- | --- |
| `closing_line` | 🔴 高优先级 | 收尾句是品牌核心文案，重复价值最高，需单独严格检测 |
| `cover_title` | 🟡 中优先级 | 封面标题重复容易被用户感知 |
| `page_title` | 🟢 低优先级 | 正文页标题可能自然相似 |
| `page_small_text` | 🟢 低优先级 | 小字描述可能自然重叠 |
| `cover_subtitle` | 🟡 中优先级 | 副标题重复也需要注意 |
| `column_label` | ⚪ 不查重 | 栏目名是分类，不是文案 |

### 6.3 阈值建议（V1.0 人工校准前的初始参考）

> ⚠️ **以下阈值为初始参考，未经真实数据校准。正式上线前必须人工校准。**

| 比较类型 | 初始阈值 | 说明 |
| --- | --- | --- |
| `closing_line` 候选 | Jaccard ≥ 0.4 | 收尾句通常很短，阈值可以低一些，宁可多报候选 |
| `cover_title` 候选 | Jaccard ≥ 0.5 | |
| `page_title` 候选 | Jaccard ≥ 0.6 | |
| `page_small_text` 候选 | Jaccard ≥ 0.5 | |

**注意**：Overlap Candidate 只是候选，不是判定。最终必须人工确认。

## 7. 收尾句单独规则

### 7.1 为什么单独处理

- 收尾句通常很短（1-2 行），与长正文使用同一阈值会导致误报率过高或漏报。
- 收尾句是品牌核心资产，重复检测价值最高。
- 收尾句有明确的查重历史（台账已存在），需要与既有规则对齐。

### 7.2 收尾句检测流程

1. **Exact 检测**：先跑原文 Exact 和 Normalized Exact。
2. **Overlap 检测**：对非 Exact 的收尾句跑 3-gram Jaccard。
3. **历史参考比对**：与台账中六张历史栏目固定收尾句比对。
4. **人工确认**：所有候选必须人工审核，不自动判死刑。

## 9. 明确不做的事

- ❌ 不使用 Vector DB / Embedding
- ❌ 不自动判定为 duplicate（所有候选必须人工确认）
- ❌ 不删除所有中文标点后做 Exact 判定（只用于 Overlap 候选发现）
- ❌ 不把视频专属收尾句混入正式查重库
- ❌ 不把整篇所有文本拼接成一个字符串做相似度
